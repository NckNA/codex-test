# Правила работы ИИ (AI Workflow)

Перед выполнением каждой задачи ИИ **ОБЯЗАН** прочитать следующие файлы:
1. `_ai_work/PRODUCT_CONTEXT.md`
2. `_ai_work/ARCHITECTURE_CURRENT.md`
3. `_ai_work/PROJECT_ROUTES.md`
4. `_ai_work/MEDICAL_DOMAIN_RULES.md`
5. `_ai_work/STORAGE_RULES.md`
6. `_ai_work/CURRENT_TASK.md` (или соответствующий файл в `_ai_work/TASKS/`)

## Основные правила выполнения задач:
- **Выбирать нужный маршрут перед правками**: Понять, в каком контексте находится текущая задача, опираясь на `PROJECT_ROUTES.md`.
- **Не изучать весь проект без необходимости**: Сфокусироваться только на тех файлах, которые напрямую относятся к задаче.
- **Не выходить за маршрут без объяснения**: ИИ не должен трогать глобальные файлы (`main.tsx`, `Layout.tsx`, `storage.ts`), если это не заявлено в задаче. Если нужно, следует явно запросить подтверждение пользователя.
- **Не делать большой рефакторинг без отдельного задания**: Фокус должен быть только на выполнении заявленных критериев (Acceptance criteria).
- **Не менять чужие модули "попутно"**: Избегать исправлений стилей/логики в компонентах, которые случайно попались на глаза, но работают исправно.
- **Не менять storage без явного указания**: Структура хранения критична. Ее нельзя ломать или менять без явной задачи.
- **Обновлять PROJECT_ROUTES.md после изменений**: Если ИИ добавляет новые страницы, компоненты или меняет логику зависимости маршрутов, он обязан зафиксировать это в документации.
- **Создавать отчет в _ai_work/REPORTS/**: Каждая выполненная задача должна завершаться созданием детального markdown отчета о том, что было сделано, как это протестировать и какие ограничения есть.
