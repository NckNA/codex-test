# Report: 004-B.3 generate treatment plan from findings

## What was implemented

- Added a flow to create a draft treatment plan from selected clinical findings.
- Added `CreatePlanFromFindingsModal.tsx` for selecting eligible `DentalFinding` records.
- Added the "Создать план из проблем" action in `TreatmentPlansTab`.
- Generated one `TreatmentStage` per selected finding.
- Stored `findingIds` and `source: from_finding` on generated stages.
- Updated selected findings to `status: included_in_plan`.
- Displayed linked findings inside `TreatmentPlanModal`.
- Kept manual treatment plan creation available.

## Type changes

- Added `TreatmentPlanSource = 'manual' | 'from_finding'`.
- Added optional `findingIds?: string[]` to `TreatmentStage`.
- Added optional `source?: TreatmentPlanSource` to `TreatmentStage`.
- Optional fields preserve compatibility with existing treatment plans in localStorage.

## Storage usage

- Reads findings with `storage.getFindings(patientId)`.
- Reads existing plans with `storage.getTreatmentPlans(patientId)`.
- Creates generated draft plans with `storage.addTreatmentPlan(patientId, plan)`.
- Marks selected findings as included with `storage.updateFinding(patientId, finding)`.
- No new storage keys or migrations were added.

## Documentation updates

- Updated `_ai_work/PROJECT_ROUTES.md` with `CreatePlanFromFindingsModal.tsx` and the `DentalFinding` link.
- Updated `_ai_work/ARCHITECTURE_CURRENT.md` with the new treatment-plan generation component.
- Updated `_ai_work/PRODUCT_CONTEXT.md` so treatment plans no longer claim generation from problems is unavailable.
